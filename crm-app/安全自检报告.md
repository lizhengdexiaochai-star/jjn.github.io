# 商机管家 · 安全隐患自检报告

> 版本：v1.1 · 检查日期：2026-11-16 · 检查对象：`app.js`、`index.html`、`style.css`、`sw.js`、单文件版与部署包

## 一、检查方法

1. **静态代码审计**：逐条检查所有输出注入点（innerHTML / 属性）的转义情况
2. **危险 API 扫描**：检索 `eval`、`new Function`、`fetch`、`XMLHttpRequest`、`WebSocket`、`document.cookie` 等
3. **外部依赖扫描**：检索所有 `http://`、`https://` 引用
4. **真实浏览器验证**：Windows Edge 157 无头模式实际渲染两个版本，确认无运行时错误
5. **自动化冒烟测试**：17 项功能测试 × 3 个版本全部通过

## 二、总体结论：✅ 未发现高危隐患

应用是**纯本地运行**的静态网页，无服务器、无账号体系、无任何网络请求，攻击面极小。

## 三、逐项检查结果

### 1. 网络行为 —— ✅ 零外部通信
| 检查项 | 结果 |
| --- | --- |
| 向第三方服务器发送数据 | ✅ 完全没有（应用内没有任何 `fetch`/`XMLHttpRequest`/`WebSocket` 调用） |
| 外部脚本 / 字体 / 图片 / 统计埋点 | ✅ 没有（无 CDN 引用，全部资源本地或内联） |
| Cookie / 追踪 | ✅ 没有使用 `document.cookie` |
| Service Worker | ✅ 仅缓存同源静态文件（`sw.js`），不上传任何内容 |
| 代码中的 `http://`/`https://` | ✅ 仅出现在使用说明文字中，非实际请求 |

### 2. XSS（脚本注入）防护 —— ✅ 已全面转义
- 所有用户输入（姓名、电话、备注、记录内容等）在写入页面前均经过 `esc()` HTML 转义（14 处 `innerHTML` 注入点逐一核实）
- 所有数据 ID 写入 HTML 属性（`data-*`、`<option value>`）处**已加转义**，堵住恶意导入文件经属性注入脚本的路径
- 新建数据使用 `crypto.randomUUID()` 生成安全 ID
- 新增 **CSP 安全策略**（`Content-Security-Policy`）元标签：禁止加载任何外部脚本/资源，即使页面被恶意篡改也无法执行第三方代码

### 3. 导入备份文件安全 —— ✅ 已净化处理
导入的 JSON 备份可能来自不可信来源，现已做如下净化：
- 结构校验（必须包含合法的 customers / opps / records 数组，否则拒绝导入）
- **ID 净化**：非法字符或重复 ID 一律重新生成
- **阶段值校正**：非法的商机阶段强制回退为「线索」
- **字段补齐**：缺失的布尔字段补默认值
- 导入内容渲染时同样经过 HTML 转义

### 4. 数据存储与隐私 —— ✅ 本机存储
| 检查项 | 结果 |
| --- | --- |
| 数据存放位置 | ✅ 仅浏览器 localStorage（键名 `shangji-crm-db-v1`），不上传 |
| 数据加密 | ⚠️ 明文存于本机（这是所有纯本地应用的共性） |
| 设备丢失/浏览器清空 | ⚠️ 数据会随之丢失 → 需定期「导出数据备份」 |
| 备份文件本身 | ⚠️ 导出 JSON 含全部客户隐私，请妥善保管，勿随意分享 |

### 5. 代码健壮性
- ✅ 删除客户级联清理关联商机与记录；删除有二次确认
- ✅ 异常导入/损坏本地数据时自动降级为空库，不会白屏
- ✅ 兼容性：移除 ES2017 语法，支持至 2016 年前后的旧浏览器内核；CSS 提供旧内核回退
- ✅ **新增运行错误自诊断**：脚本出错时页面顶部显示红色错误条并注明具体原因（替代之前的"静默白屏"）

### 6. 部署环境相关风险 —— ⚠️ 需用户注意
| 风险 | 说明 | 建议 |
| --- | --- | --- |
| 页面链接公开 | GitHub Pages 免费仓库是公开的，任何人拿到链接都能打开应用（但**只能看到自己浏览器里的数据**，看不到您的数据） | 可接受；如介意，仓库可设 Private + Pages 需付费方案，或改用私有部署 |
| 无多设备同步 | 各设备数据独立存储，互不同步 | 用「导出/导入备份」迁移；这是设计取舍，避免数据经过第三方服务器 |
| 明文 HTTP 访问 | 若部署在无 HTTPS 的空间，数据虽不出本机，但页面本身可被中间人篡改 | 使用 GitHub Pages 等自带 HTTPS 的平台 |
| 浏览器内核过旧 | 2015 年以前的浏览器不支持 | 使用系统自带浏览器或升级 |

## 四、风险等级汇总

| 风险 | 等级 | 处置 |
| --- | --- | --- |
| 数据泄露到第三方 | 无 | 应用无任何网络通信 |
| XSS 脚本注入 | 低 | 全面转义 + CSP + 导入净化（本次已加固） |
| 数据丢失（清缓存/换设备） | 中（可用性风险） | 定期导出 JSON 备份 |
| 备份文件外泄 | 中（取决于用户习惯） | 备份文件妥善保管 |
| 公开链接被他人使用 | 低 | 数据按浏览器隔离，无共享风险 |

## 五、结论

**未发现"隐患级"安全问题。** 本次自检额外加固了：属性级转义、导入数据净化、CSP 策略、运行错误自诊断，并已通过真实 Windows 浏览器渲染验证。
